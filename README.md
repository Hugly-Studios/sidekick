# Sidekick

Расширяемая menu-bar платформа продуктивности для macOS 26. Одно приложение, в которое модулями добавляются повседневные улучшения работы с ноутбуком.

- **Workspaces** — готов: снимок всех рабочих столов, открытых приложений и позиций окон с восстановлением после перезагрузки, плюс фиксация порядка рабочих столов.
- **Sounds** — кто держит аудиовыход (сейчас и недавно) и как это выключить: mute одного приложения или закрыть его.

Дальше по плану:
- **Awake** — запрет сна, в том числе с закрытой крышкой, таймерные сессии и предохранители по заряду и температуре.
- **Dictation** — надиктовка текста по горячей клавише через on-device распознавание macOS 26.
- **Messages** — перехват кодов из SMS, пришедших на Mac через Continuity, и копирование их в буфер обмена.

## Требования

- macOS 26 или новее
- Xcode 26.6
- [Tuist](https://tuist.dev) и остальные инструменты пинит [mise](https://mise.jdx.dev). `make setup` ставит их сам.

## Начало работы

```bash
make setup   # mise, подпись, зависимости, генерация проекта
make run     # собрать и запустить
make doctor  # как приложение установлено и доступно ли оно
make update  # git pull --ff-only, поставить, прогнать smoke
```

## CLI

Установленная копия отвечает на команды, пока GUI запущен:

```bash
scripts/sidekick.sh status --json
scripts/sidekick.sh features enable workspaces --json
scripts/sidekick.sh run workspaces.capture --json
scripts/sidekick.sh doctor --json
scripts/sidekick.sh logs --since 10m --level error --json
```

Подробности — [docs/cli.md](docs/cli.md). Обновление на этой машине: `make update`.

## Рабочие столы: как пользоваться

1. Включите модуль «Рабочие столы» в настройках, раздел «Модули».
2. Выдайте доступ к управлению компьютером, когда система спросит — без него нельзя ни прочитать положение окон, ни расставить их. Проверить статус: `make doctor`.
3. Расставьте столы и окна как нужно и нажмите «Сохранить состояние» в панели модуля.
4. Включите «Восстанавливать при входе в систему» и «Запускать при входе в систему» в разделе «Общие» — после перезагрузки раскладка восстановится сама.

Снятие снимка и восстановление на пару секунд пролистывают рабочие столы — это не спецэффект. Accessibility показывает только окна **видимого** стола, поэтому единственный способ узнать (и задать) положение окон на других столах — побывать на каждом. По окончании приложение возвращается на тот стол, где вы были.

Что важно знать про ограничения macOS:

- Порядок столов защищается тем, что выключается системная автоперестановка (`mru-spaces` в параметрах Dock). Программно **переставить** столы обратно нельзя — если порядок уже сбился, приложение сообщит об этом, а вернуть их местами можно только вручную в Mission Control.
- Количество обычных столов сохраняется между перезагрузками. Если столов стало меньше, чем в снимке, приложение попросит создать их: создавать столы программно macOS не позволяет.
- Полноэкранные приложения живут в собственных столах. Их полноэкранное состояние восстанавливается, но точное место такого стола в общем порядке macOS определяет сама.
- Содержимое окон (открытые документы, вкладки) не восстанавливается — это делает каждое приложение само.

## Как добраться до приложения

Приложение живёт в строке меню и не имеет иконки в Dock. Есть три способа его открыть, потому что иконка в строке меню не всегда доступна:

1. Горячая клавиша **⌃⌥⌘S** — работает всегда, меняется в настройках.
2. Иконка в строке меню.
3. Повторный запуск приложения — открывает окно вместо второй копии.

Про строку меню важно знать: на Mac с вырезом заполненная строка меню прячет новые иконки **за вырезом**, и приложение выглядит как незапустившееся. `make doctor` измеряет это и говорит прямо, видна иконка или нет.

## Подпись и повторные установки

По умолчанию сборка подписывается ad-hoc, чтобы собираться на любой машине и в CI. Ad-hoc подпись меняется при каждой сборке, а macOS привязывает выданные разрешения к паре «bundle id + команда подписи» — поэтому с ad-hoc разрешения сбрасываются после каждой пересборки.

`make setup` создаёт `Config/Signing.local.xcconfig` (в `.gitignore`) с вашей Apple Development идентичностью, и разрешения перестают сбрасываться. Team id берётся из поля OU сертификата: значение в скобках в имени сертификата — это идентификатор пользователя, и подпись с ним падает с сообщением про отсутствующий «Mac Development» сертификат.

`make install` всегда ставит приложение в `/Applications/Sidekick.app`. Один и тот же путь плюс одна и та же команда подписи — это то, что позволяет переустанавливать программу сколько угодно раз, не теряя ни разрешений, ни элемента входа в систему.

Чтобы честно проверить первый запуск, есть `make purge` (снести всё) и `make reset-permissions` (забыть только разрешения).
